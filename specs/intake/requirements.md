# 接单建项一期

用户已通过“调用软件开发的相关 skill，为我完成”确认上一轮方案，按其推荐的一期闭环实施。

1. 当 Agent 输入客户对话或截图的结构化提取结果时，系统应保存委托草稿、材料引用、字段证据和待确认问题。未知字段允许为空；不能把推测当确认。
2. 当导入源文件时，系统应复制并校验文件，使用现有转换器提取原文，输出按文件统计的 CAT 词数、非空白 Unicode 字符数、汉字数及局限说明。失败不产生可用报价快照。
3. 当输入已明确的币种、单价和计费口径时，系统应以十进制定点计算报价，保留数量、舍入规则和报价版本。应收仅由已确认报价产生。
4. 当创建项目时，系统应验证必填项、文件快照和需求确认，使用稳定的委托 ID 保证重试不产生重复项目。
5. 当 AI 获取项目简报时，系统只提供翻译目的、受众、语气、领域、语言、术语、风格、交付要求和 AI 使用限制，不提供客户联系、金额或原始对话。
6. 当记录收款时，系统应保留唯一记录 ID、币种、金额、日期和备注，拒绝重复入账或币种不一致。
7. Projects 应提供接单建项入口；用户可查看和编辑草稿、选择文件、分析、报价、建项及收款。

不包括：完整 CRM、税务发票、自动向客户发消息、OCR 引擎、自主理解截图的内置模型、TM 折扣、传统 MT 的通用自定义提示词。截图理解由当前外部多模态 Agent 完成。失败的文件计数不得假装完整。
